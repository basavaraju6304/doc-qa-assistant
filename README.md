# Document Q&A Assistant (RAG)

A Spring Boot REST API that lets you upload documents (PDF, DOCX, TXT) and ask questions about them.
Answers are generated by an LLM **only from the uploaded documents**, and every answer includes the source file name.

## Tech stack
- Java 21, Spring Boot 4.1
- Spring AI 2.0 (ChatClient, EmbeddingModel, VectorStore)
- Google Gemini (chat + embeddings)
- Apache Tika (text extraction from PDF / DOCX / TXT)
- Maven

## How it works (RAG)

```
Upload:  file -> Tika (extract text) -> TokenTextSplitter (chunks) -> embeddings -> vector store (saved to disk)
Ask:     question -> similarity search (top 4 chunks) -> prompt with context -> Gemini -> answer + sources
```

- **Retrieval:** the question is embedded and matched against stored chunks.
- **Augmentation:** the matching chunks are placed into the prompt as context.
- **Generation:** the model answers using only that context. If the answer is not in the documents, it says so.

## Project structure

```
config/      VectorStoreConfig     - shared vector store, loads saved data at startup
controller/  DocumentController    - POST /api/docs/upload
             RagController         - GET  /api/rag/ask
service/     DocumentService       - read, split, embed, store
             RagService            - retrieve, build prompt, call LLM
dto/         AnswerResponse        - { answer, sources }
```

## API

**Upload a document**
```
POST /api/docs/upload
Body: form-data, key "file" (PDF, DOCX or TXT)
Response: Stored 5 chunks from resume.pdf
```

**Ask a question**
```
GET /api/rag/ask?question=What technologies are mentioned?
Response: { "answer": "...", "sources": ["resume.pdf"] }
```

## Run locally

1. Install JDK 21.
2. Create a Gemini API key at https://aistudio.google.com/apikey
3. Set it as an environment variable (never commit it):
    - Windows: add a user variable `GEMINI_API_KEY`
4. Check the model names in `src/main/resources/application.properties` (provider model names change over time).
5. Run:
```
   ./mvnw spring-boot:run
```
6. Test with Postman using the endpoints above.

## Notes and limitations
- The vector store is Spring AI's `SimpleVectorStore`, persisted to `data/vectorstore.json`.
  It is accessed through the `VectorStore` interface, so it can be replaced by PostgreSQL + pgvector without changing the services.
- Uploading the same file twice stores duplicate chunks.
- Chunks are not filtered per user. A multi-user version would add user ID metadata and filter searches by it.

## Possible improvements
